# 足球多场后台分析

Web 首次获取赛程和可用缓存后，将未完成比赛提交给后台任务；40场只需一次提交。
保持现有卡片、百分比和预测算法，每完成一场就可展示。原单场和同步批量 API 继续兼容。

## 执行与等待

- `POST /api/predict/batch/start`：`{"matches": [...], "force_refresh": false}`，最多80场，返回202及任务状态。
- `GET /api/predict/batch/status?job_id=...&after_revision=N`：返回计数与游标之后新增的单场结果，不抓取赛程或赔率。
- 新任务队列固定2个实际分析线程，最多160个待处理工作、32个任务。相同输入的活动任务和重叠场次复用计算。
- 默认单场等待45秒，从实际开始执行时计时；环境变量 `FOOTBALL_ANALYSIS_MATCH_TIMEOUT` 可调整（有限正数，非法值回退45）。队列等待和整轮任务最多20分钟。
- Web 每秒读取一次进度，单次控制请求最多10秒、最多3次尝试；首次赛程请求最多30秒。网络中断保留已完成结果，刷新可以接续仍在执行的任务。
- 排序仅重绘；切换模块取消浏览器等待，后台共享计算继续运行。任务过期或服务重启时提示刷新，不回退成几十个同步单场请求。

## 资源与边界

复用现有URL去重、每秒请求限速、页面缓存和全局抓取并发限制。单场预算通过 ContextVar 传到五路赔率子任务，约束排队、限流等待、重试、重定向及分块读取；过期后不接受新的任务结果。盘口输入变化、显式强制刷新不会复用另一组输入的在途分析。

Python线程不能安全地强行终止。任务到期可以立即对外标记超时，但真实工作线程保持占用，直到其赔率子线程及同步调用退出，不通过新开线程替换。DNS、数据库同步读写等阻塞仍可能超过45秒；45秒是单场对外等待期限，并非保证线程45秒内退出。结果计算完成后沿用原流程先缓存再保存记录；已经开始的持久化不可回滚，保存后若预算已过期不再重新发布缓存。后台任务超时不代表数据库事务已被强制取消。

任务状态保存在单进程内存，沿用当前单worker部署。终结任务保留最多30分钟，可释放的终结结果默认最多256场，超限按完整旧任务淘汰；仍有实际线程运行的任务暂不淘汰。新任务不额外写比赛历史副本，现有缓存和预测记录保存逻辑继续使用。服务进程重启后任务ID失效，成功预测仍由原有持久化缓存恢复。多进程部署需要另行接入共享任务存储和分布式队列。

## 验证

离线测试运行真实后台队列、API路由与浏览器JS，替换外部抓取，覆盖40场提交、39场先完成而慢场超时、实际并发上限、重复提交复用、增量结果、晚返回隔离、有限重试、旧页面响应隔离、上下文一致时保留旧结果及排序不重算。该测试验证调度和恢复能力，不代表线上40场的真实耗时或源站可用率。
