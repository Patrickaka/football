# 大比分识别与大小球变化（2026-09-08）

比分 Top3 是三个具体比分的概率排序，不是总进球区间排序。比如主客进球均值
都为 1.8 的 Poisson 矩阵，前三仍是 1-1、1-2、2-1，但 4 球以上的总概率约
48%。这部分质量分散在 2-2、3-1、1-3、3-2 等比分中，不能为了显示大比分
强行把较低概率的比分塞进 Top3，也不能把“4 球以上概率”标成某个比分的概率。

## 本次实现

- 大小球变化先通过现有 `implied_total_goals`，按各自盘口的走盘、半赢半输
  规则反推公平总进球均值，再比较两端变化。原来直接相减“大 2.5”和“大
  3.5”的概率，会把升盘之后正常的概率下降当成冲突。保持高盘但水位没变
  不再算升温，缺初始报价也不生成变化信号。
- 继续复用现有比分调整及最终市场锚定，不额外叠加一套大比分加权模型，
  不增加融合权重，不改推荐门禁。当前盘口本身仍决定市场总进球目标。
- HKJC 只有当前报价时，从既有 `market_timeline` 中恢复同场、同来源事件的
  最早有效赛前观测。采集时间必须带时区并早于本次预测和开赛；来源提供的
  更新时间也必须有效。旧的无时区、跨场、赛后、未来和非法快照均不使用。
  新快照带时区，记录来源事件 ID；`history_source=local_observations` 明确
  表示“本地首次观测”，不冒充供应商真正开盘。没有合格历史则照常预测。
- 缓存同时比较大小球两边赔率，同盘口但改水位也会触发重新分析。
- `model.high_score_assessment` 在合格 ML 融合之后读取最终完整矩阵，给出
  `tail_probabilities` 的 4+/5+/6+ 全场概率、大比分候选及其真实全场排名。
  这些区间相互包含，不能相加。`goal_count` 保留相同评估供保存和导出。
  不完整或非法矩阵返回不可用，不用 TopK 子集补算尾部。
- 主页面的三栏、胜平负百分比和比分 Top3 保持原样。仅在深度报告已有的
  进球数参考卡片中补充大比分概率、可用的盘口折算总进球变化。

实现不另建历史库，不增加网络请求，复用既有快照保留上限；新增输出只是少量
概率和来源字段。需要在新版本实际采集到合格的较早观测后，HKJC 变化信号才可用。

## 离线验证及限制

```powershell
.venv/Scripts/python.exe scripts/diagnose/replay_football_high_totals.py --output reports/football_high_totals_replay.json
.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider --tb=short
```

重放只读本地十份 CSV，不读写业务数据库、不搜参数。共 3,504 场，两赛季各
1,752 场，比较固定 2.5 盘口非收盘列和收盘列的公平概率。固定高球分组使用
隐含均值 ≥3.5，提供赛季、联赛、赛季×联赛的 4+/5+/6+ 发生率、覆盖率、
Brier 和二分类 LogLoss，以及同样本上的两个报价版本差异。

| 2025/26 指标 | 非收盘列 | 收盘列 |
| --- | ---: | ---: |
| 4+ Brier | 0.201679 | 0.200696 |
| 5+ Brier | 0.119158 | 0.119442 |
| 6+ Brier | 0.055216 | 0.055289 |

该赛季收盘均值 ≥3.5 的 109 场，实际 4+/5+/6+ 比例为 48.6%/25.7%/14.7%；
全体 1,752 场分别为 29.7%/14.3%/6.0%。可以区分进球偏多的比赛环境，但
5+/6+ 的收盘 Brier 略变差，不能宣称所有尾部预测都提高了准确率。

非收盘列不等于真实初盘，CSV 没有报价采集时间且全部固定 2.5 球，不能证明
跨盘口升盘策略的收益，也不是本次完整生产模型的准确率验收。收盘信息更晚，
不能当作提前数小时可用的信息。后续需使用真实赛前冻结事件按版本评价。

预测逻辑版本 `2026-09-08-total-movement-v46`，生产记录版本
`football-v2026.09.08-total-movement-20`；通过版本区分旧缓存和新预测。
