# 主玩法：选6单式、选5复式7码

本轮版本：`kl8-v10.19-joint-main-plays`。针对v10.18的共享玩法验证链路升级，默认参考号码生成参数不变。

用户的主要目标是这两个玩法每期主推的命中表现。选6仍为一组6码，选5复式仍为一组7码展开21注；不增加码池、注数或排除轮次来包装单组准确率。

## 针对当前实现的调整

- 两个玩法共用选6排名，所以验证与激活必须共同把关。候选在验证段和最终段都要与当前实际策略同场比较：两个玩法的平均命中、零命中率和中至少3/4/5个逐项不能变差；选6中6、复式池中6/7及21注选5的3/4/5命中比例也不能退步。同时保留随机基准、置换检验、累计多重试验校正及稳定性条件。
- 合验通过后只更新真正生效的共享选6策略，保存双方证据。旧的“只验证过选6”状态不再自动标成“复式也已验证”。没有双方证据的直接激活被拒绝，原参考选号仍可运行。
- 选6与复式共享试验家族及最终测试的使用边界；更换玩法名称不能重用同一段最终数据。后台优先验证这组主玩法一次，再处理其他玩法。
- 验证API完整传入频率方向和最终选池模式。当前回测不支持的最终重号上下限参数会被明确拒绝，避免静默丢弃参数后启用另一套选号。
- 候选必须包含可用的特征权重、模型权重；验证过程中期号或开奖号码发生变化，或激活时当前策略已变化，都不能沿用原证据切换策略。
- 回放中选6另列中6；复式分别统计7码池命中与全部21注选5的命中分布。同一期的21注有关联，不当作21个独立开奖样本。

默认参考权重本轮未改变，页面布局和其他预测模块未改。
