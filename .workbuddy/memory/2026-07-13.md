- `run_prediction` 新增 4 个参数：`enable_backtest`、`enable_ml`、`enable_fusion`、`compute_weights`（默认全 True，向后兼容）
- server.py `_lottery_payload` 首屏用轻量模式（全关），避免 504 超时

### 任务2：线上预测记录与结果
- 期号修复：从 `latest_issue`(已开奖) 改为 `next_issue`(下一期)，结算才能正确匹配

### 504 超时修复
- `FULL_HISTORY_FETCH_COUNT`: 5000 → 100
- `_lottery_recommend_payload`：轻量独立计算，只抓 20 期增量，不走 run_prediction

### 后区 adjacent 修复
- `_calculate_back_feature_score` 的 adjacent 排除上期开奖号自身，避免 repeat + adjacent 双重计数导致上期号码得分虚高

### 多策略推荐差异化
- `_score_based_select` 新增 `weights_override` 参数
- 热号策略：frequency(0.25)、trend(0.15)，gap(0.06) — 偏向近期热号
- 冷号策略：gap(0.25)、frequency(0.05)、trend(0.04) — 偏向长期遗漏
- 不使用时 exclude 排重，每个策略独立按自身算法产出

### server.py
- 已还原到原始状态（预热/超时相关代码已 git revert）

### 大乐透异步后台任务机制（解决504超时）
- server.py 新增 `_lottery_bg_tasks`/`_lottery_bg_lock`/`_lottery_start_bg_task`/`_lottery_bg_run` 机制
- `_lottery_fetch_payload`、`_lottery_refresh_payload`、`_lottery_ml_refresh_payload` 改为异步后台执行
  - API 立即返回 `{processing: true, task_id, message}`，不再同步阻塞
  - 后台完成后自动更新 `_CACHE` 对应缓存键
- 新增 `/api/lottery/task-status` 路由，前端可轮询任务状态
- `_lottery_start_bg_task` 支持 `cache_value_func` 参数，控制缓存存入的值（如只存 analysis 部分）
- 同类型任务重复请求时复用已有 task_id（防并发重复）
- index.html 修改：
  - `refreshLottery()` 和 `fetchLotteryData()` 支持异步模式，收到 `processing` 后轮询 `task-status`
### 大乐透后台任务超时优化（20:20 左右）
- 问题：前端轮询 300 秒后显示"后台任务超时"，但大乐透全量分析+ML 训练可能超过 5 分钟
- 改动：
  - 前端 `_pollLotteryTask` 默认等待时间从 300 秒延长到 1200 秒（20 分钟）
  - 超过 5 分钟后显示"计算量较大，请继续等待，关闭页面不影响后台运行"提示
  - 轮询超时后不再显示错误，而是显示"后台任务仍在运行中"，并提供「继续等待」「刷新页面」按钮
  - 轮询期间展示服务器返回的当前步骤 `message`（如"正在抓取最新开奖数据..."）
  - `loadLottery()` 页面加载时先检查是否有进行中的后台任务，有则自动继续等待，避免用户刷新后看到旧数据而不知任务仍在跑
  - server.py 后台函数支持 `task_id` 参数并调用 `_lottery_update_task_message()` 更新步骤消息
  - 任务状态保留数量从最近 3 个提升到最近 10 个，降低长任务被清理的概率
- 文件：`server.py`、`web/index.html`
